# Security Policy

## Reporting a vulnerability

Please **do not** open a public issue. Use GitHub's private vulnerability reporting
("Security" → "Report a vulnerability") on this repository. Include steps to reproduce,
affected versions/commit and impact. We aim to acknowledge within 2 business days and to
provide a remediation plan within 10 business days.

Please avoid accessing other users' data, degrading service, or testing against production
beyond what is needed to demonstrate the issue.

## Supported versions

Only the latest `main` (pre-1.0) receives security fixes.

## Security design

See [`documentation/security/security-and-rights.md`](documentation/security/security-and-rights.md)
for the threat model, authentication, authorisation, data protection, secrets, audit and rights
management design.

## Secrets

- Never commit secrets. Only `*.env.example` files (placeholders) are tracked.
- Local development secrets are generated by `scripts/setup-local.sh`.
- Cloud secrets live in Google Secret Manager; CI uses Workload Identity Federation.

## Dependency policy

- CI runs `pnpm audit --prod --audit-level high` and fails on any high/critical finding.
- Fix by upgrading; where a transitive fix is needed, use a `pnpm-workspace.yaml` override within
  the same major version.
- Exceptions are allowed **only** for build-time tooling or client-side code with no server
  exposure, must be listed in `pnpm-workspace.yaml → auditConfig.ignoreGhsas` with a reason, and
  must be documented here with a review trigger.
